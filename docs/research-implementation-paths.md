> 调研性质：只读。未修改 `lib/`、未修改 profile、未重启 DSH、未动 git。
> 取证对象：`D:\Program Files (x86)\dsh\resources\app.asar`（live 包已被 dsh-retry 打过补丁），
> **官方原始代码取自 `resources\app.asar.dsh-retry.bak`（未打补丁的原始包，182766714B）与
> `dsh-retry\lib\patch.js` 的锚点**。所有官方行号/偏移均指 pristine 提取件（`%TEMP%\dsh-research\pristine\lib_main.js` 等）。

## 0. 结论（先看这里）

1. **DSH 桌面端没有任何"插件可注册托盘菜单/应用菜单"的官方扩展点。**
   桌面端是三段宿主：Electron 主进程（托盘、应用菜单、更新器，**不加载 cordis**）→ Node 子进程
   `@deepseek-ai/dsh-desktop-host`（**第三方插件真正跑在这里**）→ 渲染进程（客户端 bundle 插件）。
   主进程与 Node 宿主之间只有 4 条固定 IPC 消息（`shutdown` / `quit-inspection` / `update-tasks` / 外发
   `ready`、`fatal`、`platform-session`、`shutdown-complete`），**没有重启、没有加菜单项**的通道。
2. **官方确实有"插件扩展点"，但只在两处**：
   - **客户端 slot**（`ctx.slots.register/inject`，103 个官方 seat，含 `sidebar.footer.action`、
     `settings.section`、`settings.launcher` 等）；
   - **宿主 HTTP 路由 + index 注入**（`ctx.webServer.register`、`ctx.webServer.tapIndex`、
     `webserver/index-inject` 事件 → `IndexInjection`）。
   这两者都**不依赖 app.asar 补丁**，整包更新后依然存在。
3. **账户下拉菜单（`dsh-client-ui-settings-account` 的 `AccountMenu`）的菜单项是硬编码数组，
   没有官方 seat**，现有补丁插的正是这个数组（`items: [...]` @偏移 83926-84132）。往那里加项
   **只能** asar patch 或 DOM 注入。官方给的最接近位置是 `sidebarsettings.launcher`（单槽，
   现被 `AccountMenu` 占用，`replaceRisk: "shadows-shipped-ui"`）与 `sidebar.footer.action`（在侧栏
   设置齿轮旁，list、`replaceRisk: "none"`）。
4. **"重启"本身无法变成纯进程内动作**：`app.asar` 被 DSH 以无 `FILE_SHARE_DELETE` 方式长时间打开，
   运行中不可能换包；主进程也无重启 IPC。所以当前 0.4.0 的"杀进程 → 换包 → 拉起"helper 路径
   （`lib/index.js` L373-379 注释已写死这个约束）是唯一可行机理，**任何方案都必然让应用退出并重新
   出现一次**（约 2-4 秒），差别只在"是用户点的还是它自己触发的"。
5. **推荐（见 §5）**：把 UI 入口迁到官方 slot（`sidebar.footer.action` + `settings.section` 详情页），
   重启沿用已实现的 helper 分支，**默认关闭 asar 补丁安装**（`install: false`），补丁降级为可选增强。
   - 收益：DSH 整包更新**零操作、零补丁、零自动重启**，也不再需要向 `D:\Program Files (x86)` 写文件
     （去掉管理员权限依赖与备份文件残留）。
   - 代价：入口从"托盘右键/账户下拉"变成"侧栏页脚按钮 + 设置页"，这是官方 seat 的边界，无法突破。

### 2.5 客户端 → 宿主：只能走 HTTP 路由，不能新增 remote namespace

`@deepseek-ai/dsh-api-remotes/README.md`（"Known Limitations"）：

> The capability set is fixed by explicit build-time value imports; the Client does not discover the Host's
> active Services or Remote definitions at runtime.
> Additional capabilities require an explicit `/remote` value import and mount in this assembly.

⇒ 第三方插件**无法**注册新的 `remote.*` 命名空间。跨 half 通信的正确做法就是 dsh-retry 现在这样：
宿主 `ctx.webServer.register(...)` + 客户端同源 `fetch`。

同源可行性的正向证据（桌面端）：`pristine/lib_main.js` 的 `forwardWebRequest` 把应用请求转发给
宿主（`const PLUGIN_BUNDLE_PATH = /^\/plugins\//u` 专门放行插件 bundle），只剥掉
`set-cookie` / `content-encoding` 等头。0.4.0 的 `/dsh-retry/restart` 已经这样被调用，链路已验证。

### 2.6 渲染进程 preload 没有重启通道

`app.asar/lib/preload-app.cjs`（37833B、883 行）仅在 `location.protocol === 'dsh-app:' && hostname === 'app'`
时暴露 `window.dshDesktop`（`createProductApi()` @33581）：

```js

  shortcuts: { get, edit, recording, subscribe },

**没有 restart / relaunch / quitAndInstall**。渲染进程能做的只有 `DESKTOP_IPC.windowsMenu`
请求 caption 菜单（main.js @≈486200 `ipcMain.handle(...)` 里还会校验 `name` 只能是 `application`/`edit`）。

⇒ "客户端插件自己重启应用"这条路不通，必须绕回宿主 HTTP 路由 + helper。

## 3. 存在哪些官方扩展点 → 最小可行实现（Q2）

### 3.1 可用扩展点清单

| 扩展点 | 定义处 | 能做 | 不能做 |
|---|---|---|---|
| 客户端 slot | `dsh-cordis-client-runner` API 目录 @1110-5760；`ctx.slots.*` | 往 103 个官方 seat 里加 UI（含侧栏页脚按钮、设置页） | 加托盘项、加账户下拉项 |
| 宿主 HTTP 路由 | `SERVICE_API.webServer.register`（`dsh-host-webserver/lib/index.js`） | 暴露 `/dsh-retry/*`，客户端同源 fetch | 触达 Electron |
| index 注入 | `webServer.tapIndex(html => html)`、`webserver/index-inject` 事件、`IndexInjection` | 往桌面渲染进程注入 script/style/global/html，**无需 asar 补丁** | 免除"改 UI 需跟随官方组件结构"的脆弱性 |
| 宿主生命周期 | `ctx.effect` / `ctx.on('app-boot/config-reload')` | 启动自愈 | 阻止/延迟主进程启动 |

`IndexInjection` 类型（catalog `TYPE_API`）：
`{kind:'global',name,value}` | `{kind:'script',placement,text}` | `{kind:'script-src',placement,src}` |
`{kind:'script-preload',src}` | `{kind:'style',text}` | `{kind:'html',placement,html}`，`placement ∈ head|body`。
渲染实现在 `dsh-host-webserver/lib/index.js:43`；桌面链路已验证：
`dsh-desktop-host/lib/index.js:346` `injections: ctx.webServer.collectIndexInjections()` →
`process.send({type:'ready',...})` → 主进程 @144779 收、@461760 存 → `ipcMain.handle(DESKTOP_IPC.boot)`
@471200 返回 `{injections, streamBaseUrl}` → preload 暴露 `dshDesktopBoot`（`preload-app.cjs:863`）→
前端 `dsh-web-frontend/dist/assets/index-BXV-oxvX.js` @921244 的 `UZ(e,t)` switch 按 kind 应用，
@922218 桌面分支 `Ls.ready().then(async ({ injections, streamBaseUrl }) => { … await UZ(injections, …) })`。

      const [busy, setBusy] = React.useState(false);
      const onClick = async () => {
        if (busy) return;
        setBusy(true);
        try { await fetch("/dsh-retry/restart", { method: "POST", headers: { "sec-fetch-site": "same-origin" } }); }
        catch { setBusy(false); }
      };
      return React.createElement("button", {
        type: "button", title: "重启 DeepSeek Harness", "aria-label": "重启 DeepSeek Harness",
        disabled: busy, onClick, className: "dsh-retry-footer-action",
      }, "⟳");
    }

    function RestartPage() {
      return React.createElement("div", { className: "dsh-retry-page" },
        React.createElement("h2", null, "重启 DeepSeek Harness"),
        React.createElement("p", null, "修改插件/配置后重启应用与宿主进程生效。"),
        React.createElement(RestartButton));
    }

    function apply(ctx) {
      ctx.slots.inject("sidebar.footer.action", () =>
        ctx.slots.register({ name: "sidebar.footer.action", id: "dsh-retry-restart", order: 90, label: () => "重启" }, RestartButton));
      ctx.slots.inject("settings.section", () =>
        ctx.slots.register({ name: "settings.section", id: "dsh-retry", order: 95, label: () => "重启与更新" }, RestartPage));
    }

    return { inject: ["slots", "locale"], apply };
  },
});
```

> `dsh.client.inject` 的语义是"本 bundle 依赖的非 baseline 模块"，与 `require()` 的运行时依赖一一对应
> （`dsh-ppt` 注入 `ui-settings/-layout/-sidebar`，`dsh-code-review` 注入 `ui-commands/-primitives`）。
> 若 `lib/client.js` 只 `require('react')` 和 `ctx.slots`，`inject` 可留空 `[]`；一旦 `require()` 了
> `@deepseek-ai/dsh-client-ui-primitives` 里的图标/按钮组件，就必须把该包列进来，否则加载顺序不保证。

**是否需要改 `cordis.patch.yml`**：**不需要**。现有 `cordis.patch.yml`
（`- insert: [{ id: dsh-retry, name: dsh-retry }]`）已经让 dsh-retry 成为 profile loader 条目；
`dsh.client` 一旦在 manifest 里声明，`@deepseek-ai/dsh-client-modules` 会把 `./client` 变成
`/plugins` 下的 bundle 并注入 index（README L34：
"A browser plugin package declares `dsh.client` in its `package.json` with `platform: 'web'`,
exports a `./client` bundle … The host half turns each declaration into a served bundle under `/plugins`"）。
`dsh-ppt`（`settings.section`+`workbench`）就是这条路的在跑实例。

**能否热加载**：
- 首次安装 / 升级插件包：`@deepseek-ai/dsh-plugin-manager/README.md` L141
  "Package replacements require restarting the process without HMR." ⇒ **需要一次重启**（用户主动点）。
- 之后日常：profile 是 live recompose 的（L73 "A live profile recomposes, so the granted plugin mounts in
  the running session and the result reports `applied`"），启用/禁用/重载走 `hmr` service。
- **DSH 整包更新不影响 profile 里的插件**（插件在 `~/.dsh/profiles/desktop`，不在 app.asar 内）
  ⇒ 更新后**零重启**，这正是本方案对用户诉求的核心价值。

**是否还需要 asar 补丁**：**不需要**——只要入口不再是"托盘右键项 / 账户下拉项"。
补丁保留为可选增强（`install: false` 默认关闭），因为唯一必须补丁的两处就是这两个 UI 位置。

## 4. 无官方入口的替代方案对比（Q3）

先明确三条硬约束（决定所有方案的上下限）：

1. **运行中换包不可能**：`lib/index.js` L373-379 注释 —— "DSH keeps app.asar open without
   `FILE_SHARE_DELETE`, so the archive can never be replaced while the app runs, and a helper that waits
   for a later exit is torn down before it can act."

## 5. 推荐路径与改动清单（Q4）

### 5.1 推荐：方案 e 为主，c 降级为可选

排序：**e（官方 slot 入口 + helper 重启）> c（保留补丁能力但默认关闭自动重启）> a（launcher）> f（影子账户入口）> b（计划任务）> d（更新器拦截）**。

> 分数说明：§4 表里 f 得 15 分高于 a 的 13 分，但四维没有计入"破坏官方账号流"的尾部风险
> （`replaceRisk: "shadows-shipped-ui"`，一旦官方改 signin/菜单结构，坏的是账号功能而不是重启按钮），
> 所以排序上 f 放在 a 之后。

理由：用户真正的痛点不是"重启按钮点不到"，而是"DSH 每次更新都把这功能干掉，还自己重启一次"。
e 把入口搬到**不随 app.asar 更新消失**的官方扩展点上，代价是位置从托盘/账户下拉移到侧栏页脚
（紧邻设置齿轮，与账户头像同一区域，是官方 seat 里离原位置最近的一个）。补丁保留但默认不装，
于是"更新后自动重启一次"这件事**根本不会发生**。
